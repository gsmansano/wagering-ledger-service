## Decisions and notes

- **Claiming and target (#56, #57).** The publisher reuses the shape of the pending-reference worker. Events go to a FIFO queue with the wallet as group and the event id as deduplication id; delivery stays at-least-once and consumers deduplicate by `eventId`.
- **Parked events block their wallet (#58, #59).** Chosen after weighing a parked `WIN` followed by bets and losses: the money is already committed, so blocking only delays notifications, while publishing past it would leave a silent gap in a stream that carries `walletVersion`. Only the oldest unpublished event of a wallet is eligible, even while it waits for its backoff.
- **Ordering key (#60).** A global identity column rather than a per-wallet `max + 1`: no extra query on the write paths. The guarantee rests on every outbox insert happening under the wallet lock; a test pins it.
- **Requeue (#61).** A domain method and a repository update; no endpoint until real authentication exists (M12). The README will document the operator's SQL.
- A single `NOT EXISTS` over earlier unpublished rows gives the order, the block by a parked event, and the block by a row another publisher holds (still unpublished until its commit).
- Known limit: the SQS call runs inside a database transaction, so a slow broker holds a connection and a row lock. The send has a 10 s timeout; the effect is measured in M9.
- The existing migration tests count `down()` calls from the latest migration, so each new migration requires updating them.

# Session log: 2026-10-17 (second session)

## Objective

M8 — Transactional outbox, step 2: the polling worker that publishes outbox events, its configuration and wiring, and the concurrency and recovery tests.

## Completed

- Committed step 1 (`b5e79c3`) after review.
- Added `OutboxWorker`, with the same shape as the pending-reference worker: it polls, publishes until nothing is eligible or the batch is used up, survives a failed poll, and `stop()` waits for the publish in flight. A retried event is logged as a warning and a parked one as an error that names the held wallet; logs carry ids, event type, attempt count and the error message, never the payload.
- Added the `OUTBOX_*` configuration (worker switch, poll interval, batch size, retry limit, backoff, send timeout) and wired `SqsEventPublisher`, `PublishOutbox` and `OutboxWorker` into the Nest module. The worker runs in every instance and can be switched off per instance; the test setup switches it off.
- Added `outbox-worker.test.ts` (6 tests, real PostgreSQL and MiniStack): events of a committed change are published and marked; commit followed by a death before publishing is recovered by a later instance; send followed by a death before the commit is sent again and the queue keeps one copy; four instances over a loaded outbox (3 wallets, 33 events) publish every event once and keep the per-wallet order in the queue; the loop survives a refusing broker; `stop()` waits for a held send.
- Verification: typecheck is clean; the full suite passes (509 tests, 0 failures); the new file passed 3 consecutive runs. Two mutation checks failed the tests as expected: a random deduplication id (double-send test) and no ordering guard in the claim (four-instance test). A live run of the app against Compose provisioned `wager-events.fifo`, and a wallet created over HTTP had its event published by the worker.

## Files changed

- `src/infrastructure/workers/outbox.worker.ts`: new worker.
- `src/config.ts`, `.env.example`: `OUTBOX_*` settings.
- `src/app.module.ts`: providers for the publisher, `PublishOutbox` and the worker.
- `test/support/setup.ts`: `OUTBOX_WORKER=off` for tests.
- `test/integration/outbox-worker.test.ts`: new tests.

## Decisions and notes

- No new decision: the step follows #56–#61.
- The poll is the only publication path. Publishing right after the commit in the request, or waking the worker with `LISTEN/NOTIFY`, were left out: the first can be lost on a crash and the second adds moving parts for a latency the poll interval (500 ms by default) already covers.
- `tick()` has no stop guard: a guard made direct calls in tests a no-op, and the batch size already bounds a poll.
- The send-then-crash test relies on the FIFO deduplication window (5 minutes); beyond it the consumer deduplicates by `eventId` (to be written in `ARCHITECTURE.md`, M11).
- Known limits: publication latency is up to `OUTBOX_POLL_MS`, and throughput is one send per transaction per instance.

## Next steps

- M8 step 3: per-use-case checks of the emitted events (`WalletBalanceChanged` only when the balance moves, `LOSS` only `WagerTransactionProcessed`), `poc:outbox` (rows published, and what happens after a crash), the README section including the operator's requeue SQL, and ticking M8.

# Session log: 2026-10-17 (fourth session)

## Objective

M9 — Multi-instance and recovery, step 1: a harness that runs several application instances as separate processes against the same database and queues, a seeded mixed load, and a convergence check over every wallet.

## Completed

- Proposed the M9 breakdown (four steps: harness and mixed load, restart mid-load, hot-wallet experiment, `poc:multi`) and its design questions; the recommendations were accepted.
- Added `Cluster` (`test/support/instances.ts`): starts N `bun src/main.ts` processes on free ports, waits for `/health/ready`, and can kill (SIGKILL or SIGTERM) and restart an instance. Kill and restart are used from step 2.
- Added the load generator (`test/support/load.ts`). `planLoad` builds the whole load from a seed: BET/WIN/LOSS, about 10% duplicates (half over the other channel, some SQS duplicates reuse the message id to hit the inbox), reversals of earlier transactions, and reversals planned before their reference. `playLoad` runs it with a fixed number of operations in flight; HTTP deliveries rotate over the running instances, a duplicate goes to a different instance than its original, and a 503 or refused connection is resent with the same key.
- Added the convergence check (`test/support/convergence.ts`). `waitForConvergence` polls conditions, never a fixed sleep: one row per submitted transaction, none pending, wager queue empty (visible, in flight, delayed), outbox drained, on two consecutive looks. `assertInvariants` runs one SQL statement per invariant and returns the offending wallets: `balance == ledger`, a gapless ledger chain, entries matching outcomes, only `PROCESSED`/`REJECTED` left, no duplicate transactions, outbox published and nothing parked, each wallet's `WalletBalanceChanged` chain unbroken and ending at the wallet's version, empty DLQ.
- Added `multi-instance.test.ts`: 3 instances, 6 wallets opened with 300.00, 240 deliveries (about 70% HTTP, 30% SQS), 24 in flight. It also checks that no request answered 500, that duplicates answered with the original's transaction id, that every instance served requests and every wallet was reached through more than one instance, and that the mix produced processed, rejected and reversal transactions.
- Added `SQS_QUEUE_PREFIX` (empty by default) to `queue-names.ts` and `.env.example`, so the test processes own their queues.
- Verification: typecheck is clean; the new test passed with the default seed and with seeds 1, 2 and 3 (about 14 s per run); `app.test.ts` passes. A mutation check, temporarily removing `for no key update` from the wallet lock in `mikro-orm-wallet.repository.ts` and then restoring it, made the test fail (ledger-sequence unique violations, no convergence); `git diff` confirmed the file matches the commit again.
