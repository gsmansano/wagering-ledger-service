## Decisions and notes

- **Claiming and target (#56, #57).** The publisher reuses the shape of the pending-reference worker. Events go to a FIFO queue with the wallet as group and the event id as deduplication id; delivery stays at-least-once and consumers deduplicate by `eventId`.
- **Parked events block their wallet (#58, #59).** Chosen after weighing a parked `WIN` followed by bets and losses: the money is already committed, so blocking only delays notifications, while publishing past it would leave a silent gap in a stream that carries `walletVersion`. Only the oldest unpublished event of a wallet is eligible, even while it waits for its backoff.
- **Ordering key (#60).** A global identity column rather than a per-wallet `max + 1`: no extra query on the write paths. The guarantee rests on every outbox insert happening under the wallet lock; a test pins it.
- **Requeue (#61).** A domain method and a repository update; no endpoint until real authentication exists (M12). The README will document the operator's SQL.
- A single `NOT EXISTS` over earlier unpublished rows gives the order, the block by a parked event, and the block by a row another publisher holds (still unpublished until its commit).
- Known limit: the SQS call runs inside a database transaction, so a slow broker holds a connection and a row lock. The send has a 10 s timeout; the effect is measured in M9.
- The existing migration tests count `down()` calls from the latest migration, so each new migration requires updating them.
