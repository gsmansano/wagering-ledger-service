## Decisions and notes

- Queues are created by the app at startup (decision #4). `CreateQueue` is idempotent for identical attributes, so concurrent instances are safe.
- Migrations run in a one-shot `migrate` Compose service that app instances wait for (decision #5), so instances never migrate concurrently.
- Tests use a separate `wagering_test` database, migrated once per run and truncated between tests (decision #6). The truncate helper exists but is not used until M3 introduces tables with data.
- MiniStack's FIFO and DLQ behaviour is confirmed, so the LocalStack fallback from decision #2 is not needed.
- TypeScript 6.0.3 is used instead of 7.x to keep reliable `emitDecoratorMetadata` support, which NestJS dependency injection relies on.
- Migrations are registered explicitly in `migrations/index.ts` rather than discovered by glob. The MikroORM schema snapshot is disabled because migrations are written by hand.
- The AWS SDK needs credentials to sign requests even against the emulator; the test setup defaults them to `test`.
- The `skeleton_probe` migration is a placeholder to be replaced by the real schema in M3.
- Future milestones are split into 2–4 reviewable steps each, with a review after every step.

# Session log: 2026-10-15 (third session)

## Objective

Complete M2 — Domain model: the pure-TypeScript business rules, fully unit-tested, with no framework or ORM imports. Also add a hands-on PoC convention to the workflow.

## Completed

- **Money and errors.** `Money` is an immutable, scale-2 value object on `decimal.js` with strict input validation (rejects `NaN`, `Infinity`, scientific notation, empty strings, signs and more than 2 decimals). `DomainError` is the base for business-rule violations.
- **Wallet and ledger.** `Wallet` (`open`, `rehydrate`, `debit`, `credit`) changes the balance and returns the `WalletLedgerEntry` that records it, so the two cannot diverge. The entry is immutable by structure and validates its own arithmetic. A debit larger than the balance throws `InsufficientFundsError`.
- **Transactions.** `WagerTransaction` has reference rules at creation, a transition table in which `PROCESSED`, `REJECTED` and `FAILED` are terminal (`InvalidTransactionStateError`), and the queries `affectsBalance`, `requiresReference`, `matchesPayload` and `ledgerDirectionFor`. The `FailureCode` taxonomy has 11 codes, and `referenceReadiness()` decides whether a reversal waits for its reference or is rejected with `REFERENCE_NOT_PROCESSED`.
- **Messaging and events.** `InboxMessage` and `OutboxMessage` (retry with capped exponential backoff, parked after 20 failed attempts). The `IntegrationEvent` envelope with its four events: `WagerTransactionProcessed`, `WagerTransactionRejected`, `WagerTransactionPendingReference` and `WalletBalanceChanged`.
- **Hashing.** Canonical JSON and the SHA-256 `payloadHash` over the business fields.
- **Quality gates.** 148 domain unit tests (155 in the whole suite) pass and typecheck is clean. A purity test scans `src/domain` and fails on any import other than relative modules, `decimal.js` and `node:crypto`.
- **PoC.** Added the hands-on PoC convention (a PoC checkbox on M2–M9 in `PLAN.md`) and `bun run poc:domain`, a terminal tour of every domain rule.

## Decisions and notes

- **Money (#7).** `decimal.js`. `Money.from` rejects negative input as the specification requires for input contracts; `subtract` and `negate` can produce negatives, which `Wallet` uses to detect an overdraft.
- **Wallet (#8, #9).** `debit`/`credit` return the ledger entry. Ids and time (`entryId`, `now`) are passed in to keep the domain deterministic. `version` and `updatedAt` change only when the balance does. The entry is built before any field changes, so a failed movement leaves the wallet untouched. Insufficient funds is a thrown `InsufficientFundsError`; the use case is expected to catch it and reject with `INSUFFICIENT_FUNDS`.
- **Open question for M4.** `Wallet.open` returns only the wallet, so the opening balance has no ledger entry yet. Whether `open` or the `CreateWallet` use case produces the `OPENING` entry is settled in M4.
- **Transitions (#10).** `PENDING` can go to any other status; `PENDING_REFERENCE` to `PROCESSED`, `REJECTED` or `FAILED`; terminal states to nothing. `PENDING_REFERENCE` does not transition to itself, since retry counting belongs to the M5 worker. `reject` and `fail` take a timestamp, like `markProcessed`.
- **Reference rules (#11).** A `BET` or `OPENING` with a reference is an invalid payload (`create` throws, nothing persisted, no failure code); `REFUND` and `ROLLBACK` require one. A `WIN` or `LOSS` may carry one, kept as information and never blocking processing. `ledgerDirectionFor` throws for `LOSS` (callers check `affectsBalance()` first); `ROLLBACK` is the inverse of its reference. The cross-transaction reversal checks are deferred to M5. To be noted in `ARCHITECTURE.md`.
- **Failure codes (#12).** `REFERENCE_NOT_PROCESSED` applies only when the reference is `REJECTED` or `FAILED`; a missing, `PENDING` or `PENDING_REFERENCE` reference means wait. `referenceReadiness()` uses an exhaustive status switch, so a new status will not compile until it is classified. `PROCESSING_FAILED` is exclusive to `FAILED`. `create` requires a positive amount for every kind except `LOSS`, which may be `0.00`.
- **Backoff and parking (#13).** `min(1s × 2^(attempt−1), 5 min)`, without jitter, as the shared pure function `exponentialBackoffMs`. An outbox message is parked (`failedAt` set, never deleted) at the 20th failed attempt, about an hour of retrying, so a poison event cannot retry forever. Whether a parked event blocks later events of the same wallet is decided in M8.
- **Payload hash (#14).** SHA-256 of the canonical JSON (keys sorted recursively, no whitespace) of `providerId`, `externalTransactionId`, `playerId`, `walletId`, `roundId`, `gameId`, `kind`, `money` (normalized to scale 2) and `referenceExternalTransactionId` when present. The `Idempotency-Key` header and transport metadata are excluded. To be documented in `ARCHITECTURE.md`.
- **Events (#15).** `aggregateId` is the `walletId` on all four events; the outbox row id is the event id; `data` carries `MoneyProps`, never `Money`; ids and time arrive through an `EventContext`.
- The test preload connects to PostgreSQL, so even pure domain tests need `postgres` and `ministack` running (`docker compose up -d postgres ministack`).
