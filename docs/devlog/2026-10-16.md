## Decisions and notes

- **Mapping (#16).** ORM mappings will be `EntitySchema` files in infrastructure with mapper functions calling `rehydrate`; no decorators on domain classes.
- **Ledger immutability (#17).** A row-level trigger rejects `UPDATE` and `DELETE`, so it holds for any writer. `TRUNCATE` is not blocked, which the test truncate helper relies on.
- **Types (#18).** `uuid` ids and `NUMERIC(19,2)` money. Enum-like columns are `text` with `CHECK` rather than Postgres enum types, so adding a value is a one-line constraint change.
- **Replays (#19).** `wager_transactions.balance_after` stores the balance observed at settlement, because `LOSS` and rejections have no ledger entry to derive it from.
- **Opening (#20).** The opening credit is a real transaction row (`kind = OPENING`, provider `SYSTEM`, external id = wallet id), which settles the M2 open question and keeps the ledger foreign key uniform.
- The reversal uniqueness is a partial unique index over `PROCESSED` reversals only, so a rejected reversal does not block a later valid one. A wallet has at most one `OPENING` row (partial unique index).
- The migration is appended rather than replacing `skeleton_probe`, so databases that already applied the placeholder keep working.
- `reference_attempts` and `reference_next_attempt_at` were added to `wager_transactions` as the retry state of the M5 pending-reference worker (and to back the "due" index); the domain entity does not carry them yet.
- Not enforced in the database by design: `wallet.balance` equal to the latest ledger `balance_after` (checked by reconciliation, M9) and protection against lost updates (locking, M4).
- Unit tests stay next to the code (`*.spec.ts`); integration tests stay in `test/integration/`.
- Git rename detection: files were moved without `git mv` to avoid staging; they appear as renames once staged.
